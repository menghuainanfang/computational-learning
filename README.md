# Computational Learning

汇总本科课程中需要编程的练习、作业、实验和项目，通过自己实现代码，把理论理解转化为可运行、可验证的结果。

本学期聚焦 **数值分析、数据结构与算法、机器学习**，同时使用 **C、C++ 和 Python**。按问题与学习目标选择语言；需要比较实现时，在同一专题中保留多个语言版本，不要求每道题机械地重写三遍。

## 组织方式

一门课一个目录，一个专题或作业一个子目录。下面的 `topic-name` 是组织示例，尚未创建；只建立实际需要的目录。

```text
computational-learning/
├── README.md
├── .gitignore
├── numerical-analysis/
├── data-structures-and-algorithms/
├── 最优化/
│   ├── README.md
│   └── 梯度下降法/            # MiniOpt Python 包、实验与测试
└── machine-learning/
    ├── README.md
    └── topic-name/             # 示例专题
        ├── README.md          # 题目、思路、运行方式与结论
        ├── c/                 # C 实现（按需）
        ├── cpp/               # C++ 实现（按需）
        ├── python/            # Python 实现（按需）
        └── tests/             # 测试用例、小型数据与预期结果
```

跨语言实现尽量使用相同输入和评价标准。浮点结果按误差容限比较，不要求逐位一致。

## 语言与运行环境

- **C**：用于显式的数据表示、内存管理和算法实现。记录所用 C 标准、编译器版本、编译与运行命令。
- **C++**：用于类型、抽象、泛型和算法实现。记录 C++ 标准和构建方式；说明标准库的使用范围。
- **Python**：用于算法原型、数值实验、数据处理和可视化。记录解释器版本与必要依赖；不同任务存在依赖冲突时使用独立环境。

不在仓库中硬编码个人电脑的解释器路径。每个任务的 README 提供经过实际验证的命令；多文件 C/C++ 项目按需使用 CMake，Python 任务按需提供依赖文件。不为尚未开始的任务预装依赖。

## 每个任务需要记录什么

1. **问题与来源**：题目、输入输出、约束，以及教材章节或参考链接。
2. **实现思路**：算法原理、关键步骤、数据结构与语言选择。
3. **运行方式**：工作目录、工具版本、依赖、编译或运行命令。
4. **验证与结论**：测试用例、预期结果、误差或评价指标，以及不足和改进方向。

任务状态可使用“未开始 / 实现中 / 已验证”。“代码能运行”不等于“结果已验证”。

## 学习与代码来源

核心算法由本人实现。教材、论文、第三方实现和辅助工具用于理解、检查、调试与对照，引用时注明来源及用途。直接调用库函数作为基准时，与自己实现的算法明确区分。

保留值得回顾的错误分析与实验结论。辅助工具是否直接编写完整实现，以具体任务的明确要求为准。

## 文件与版本管理

- 提交源代码、说明、必要的小型测试数据和有意义的实验结论。
- 忽略虚拟环境、编译产物、缓存及可重新生成的输出，具体规则见 [.gitignore](.gitignore)。
- 大型数据与模型参数另行存放，记录来源、获取方式或生成步骤；不提交密钥及本机凭据。
- 一次提交围绕一个明确变化，例如 `数值分析: 实现二分法并验证误差` 或 `docs: 更新课程说明`。
- 推送前检查修改范围并完成与改动相称的验证；实验性改动可使用独立分支。

新增课程时，沿用“课程目录 + 简短说明 + 按需增加任务”的结构。
